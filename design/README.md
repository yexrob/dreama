# depth3d 头显端 UI/UX 设计交付

本目录包含 depth3d（PICO 4 / OpenXR「2D → 实时 3D 影院」）头显端的完整 UI/UX 规范与离线可交互 HTML 视觉稿。全部设计围绕**透视真实房间可读性**、**无键鼠（手柄射线 + 裸手捏合）大热区操控**、以及 **OpenXR 16 个合成层硬限制** 展开。

## 关键设计决策与取舍

### 1. 一级导航：「点播媒体库」与「即时画面输入」解耦
- **决策**：采用左侧空间导航轨，将**「投屏与串流」**独立为一级导航入口（并在首页右上角提供绿点脉冲状态胶囊一键直达），而不是塞进「播放源」或「设置」里。
- **取舍**：媒体库（`Source → Category → Item`）是选片点播心智；AirPlay 镜像、DLNA App 投屏、Mac/PC 串流则是“把旁边设备正在放的画面拉进头显转 3D”的即时输入心智。合并在「投屏与串流」下通过双 Tab 区分，既避免一级导航过多，又让用户拿起 iPad 或想连 Mac 时一眼找到入口。同时默认支持后台静默待命接收投屏，减少切页成本。

### 2. VR 播放场景：合批贴图取代逐按钮独立合成层（死守 16 层红线）
- **决策**：由代码（`xr_layers.c`）可知 PICO 4 与 Quest 3 均强制限制单帧最多 **16 个 OpenXR 合成层**。相比 MoonlightXR 早期在画面下方拆出 7–8 个独立按钮层的设计，本次将整个底部控制条（播/停、±10s、时间轴、3D 开关、字幕音轨、屏幕环境、快捷菜单、退出）**合批为 1 张 Canvas 贴图四边形（1 层）**，快捷菜单同样合批为 **1–2 层**。
- **收益与取舍**：即使在最重场景（3D 影厅 + 氛围光 + 3D 双目视频 + 立体字幕 + 播控条 + 快捷菜单 + 射线光标 + Toast），总层数也仅 **11 层**，留出 4–5 层给双目立体字幕或手柄模型；代价是按钮无法独立做各自硬件层级缩放，需通过 Java Canvas 局部重绘或单张高亮层呈现悬停态（在 Android 端重绘 1920×176 位图耗时极低，仅指针命中区域变化时才重绘上传，完全可控）。

### 3. 无键盘输入：「局域网自动发现 + 手机扫码填写」优先，系统键盘仅兜底
- **决策**：在 VR 里用射线逐字输入 WebDAV 地址、Jellyfin 密码、插件仓库 JSON 链接或 TMDB API Key 体验极差。因此设计了四级降级：Bonjour 自动发现 → 弹窗内置「手机扫码网页填写」实时回填（复用了产品方案中的局域网手机网页遥控服务） → 搜索页优先语音与筛选标签 → 最后才唤起 PICO 系统键盘。
- **取舍**：需要在头显 App 内内置一个轻量局域网 HTTP/WebSocket 页面，但它同时服务于「手机网页遥控器」「插件仓库粘贴」「媒体源配网」三个高频场景，投入产出比极高。

### 4. 透视环境与 PICO 4 光学适配：高不透明度暗墨玻璃 + 中文 18 sp 下限
- **决策**：主窗口底色采用 `rgba(13, 16, 23, 0.88)` 的深海暗墨高不透明度磨砂基底，而非 30%–50% 的通透玻璃；中文正文严格以 `18–20 sp` 为下限，主文字用 `#F4F7FB` 替代纯白 `#FFFFFF`。
- **取舍**：放弃了部分“极轻极透”的视觉噱头，换来的是白天阳光客厅（亮透视）和夜间暗房都能稳定保持 ≥ 13:1 对比度、简体中文在 PICO 4 约 20.6 PPD 下无笔画粘连、且减少 Pancake 镜片的纯白鬼影眩光。

### 5. 播放中交互：控制条悬停保活 + 快捷菜单位姿冻结 + 字幕空间深度
- **控制条保活**：修正旧版 `LocalPlayerXR.java` “3 秒未移动即隐藏”在停驻读菜单时意外消失的问题——射线停在控制条或快捷菜单热区内时暂停倒计时。
- **位姿冻结**：快捷菜单打开后冻结空间位置并偏置到右下/中下（沿用 `xr_ui.c` 的思路），拖动屏幕大小或距离滑块时，菜单不会跟着屏幕跑掉，且画面主体依然可见以便实时观察 3D 效果。
- **字幕空间深度**：在快捷菜单和全局设置中都将「字幕空间深度」作为一等公民控件，直接解决 3D 观影中字幕平面与前景物体深度冲突导致重影眼累的真实痛点。
