# 任务 G：手柄调色板、弹幕、字幕、屏幕操控

## 目标

本地/插件视频播放（`LocalPlayerXR`）时：

1. 指着画面按住扳机（或握把）推摇杆，调屏幕远近和大小；曲度连续可调。
2. 播放设置挪到挂在手柄上的调色板，可钉在空中。
3. 画面上显示弹幕，有「漂浮感」和「层次」，沿曲面屏飘过。
4. 画面上显示静态字幕，和弹幕共用漂浮感。

## 以设计为准

`design-opus/ux-spec.md` 是这一轮的唯一行为与视觉依据：§6.1、§6.3（调色板）、§6.4（按键 × 状态表与判定规则）、§6.5（图层预算）、§6.10（弹幕）、§6.11（字幕）、§6.12（屏幕操控）、§3.8（设置页默认值）、§7 里的落地说明、§8 待验证清单。画稿 `design-opus/mockups/vr-palette.html`（17 个状态）。尺寸、阈值、默认值、文案、行的顺序一律照规范，不要自己发明；规范里互相矛盾或做不到的地方，停下来写进回报，不要猜。

另读：`docs/specs/00-quality-bar.md`、`docs/specs/plugin-host-integration.md`、`docs/specs/plugin-protocol.md`（`danmaku` 能力）。

## 现状（已核实，供定位）

- 渲染器 `player/app/src/main/jni/xr-renderer/`：`xr_layers.c`（每帧组层；视频层按眼拆分、`curve>0.01 && cylinderSupported` 时用柱面层；进度条层永远是平面）、`xr_input.c`（动作绑定、`applyGrab` 的 `GRAB_MOVE/GRAB_RESIZE`、摇杆 y→滚动、`writeInputPose`/`nativeSetScreenPose` 十个值）、`xr_ui.c`（`effectiveCurvature`、屏幕页滑条）、`xr_math.c`（`cylinderAngle`、`screenProject`、`curveLocal`）、`xr_session.c`（`cylinderSupported`、`maxLayerCount` 钳到 16）、`xr_assets.c`（`uploadArt` 整图上传）、`xr_notice.c`（toast 层）。
- 每手都有 `gripSpaces[h]`，目前只给手柄模型用。
- 所有面板由 Java 用 Canvas 画（`binding/video/XrPanels.java`、`local/TransportBar.java`），C 只管位姿和命中。
- `LocalPlayerXR.java`：Media3 1.11.1，无 `media3-ui`；选了文本轨但没有 `onCues` 消费者；摇杆左右 ±10 秒（`onVrScroll`）；扳机点画面＝播放/暂停（`onVrButton`）。
- 插件外挂字幕经 `PlaybackMediaSourceFactory` 的 `SingleSampleMediaSource` 合并；Media3 新版默认在提取阶段解析字幕，这条路可能需要调整才会出 Cue——**先验证再决定改法**。
- 插件运行时已有 `DanmakuItem` / `PluginProtocolMapper.mapDanmaku`，没有界面消费者。
- 设置：`seekbar_vr_distance`、`seekbar_vr_screen_size`、`seekbar_vr_curvature`、`vr_screen_pose`；设置页「曲面屏」是开关（写 45 或 0）。

## 分阶段，每阶段单独提交、单独可用

### G1 屏幕操控与连续曲度
- §6.12 全部：扳机/握把按住 + 摇杆调远近与大小、锁轴、档位吸附与振动、读数提示（复用 toast 层）、松开保存、B 撤销。§6.4 判定规则逐条实现（350 ms、摇杆阈值、进入调整后松开不触发播放/暂停、调整期间抑制快进快退）。
- 判定逻辑写成不依赖 OpenXR 的纯函数（C 里单独一个文件加主机端单元测试，或放到 Java 侧），输入是时间戳和摇杆/扳机采样序列，输出是动作；用表驱动测试覆盖 §6.4 表里每一格。
- 曲度：设置页开关改为连续值；进度条、弹幕、字幕在曲面屏上贴合柱面（进度条现在是平的，需要一起修）；`cylinderSupported` 为假或房间环境时按规范置灰并写原因。
- 现有握把拖动、抓角缩放、位姿持久化不回退。

### G2 调色板
- §6.3 全部：挂在手上（grip 位姿 + 规范给的偏移与倾角）、钉住/取回、标签页、每行的摇杆调值与复位、置灰原因、换手设置、手势追踪下的等价操作。
- 一层、1024×768、只在内容变化时重画和上传；悬停高亮不得触发整图重传以外的额外层。
- 命中测试：射线来自另一只手；拿面板的手的射线不参与命中。面板非模态（规范写明）。
- 原齿轮面板里与本地播放重复的项按规范处理；PC 串流场景的现有面板不改。
- 调色板的状态机（当前页、焦点行、钉住、各行的值与可用性）用纯 Kotlin/Java 类实现并做 JVM 测试；绘制与 JNI 保持薄。

### G3 静态字幕
- 消费 Media3 的文本 Cue 和位图 Cue（PGS 等），按 §6.11 排版；位图字幕只缩放和定位。
- 一层，仅在 Cue 变化时重画；深度按漂浮感设置放在屏幕前（真实几何距离），曲面按字幕曲度设置。
- 字幕轨/音轨选择接到调色板；内嵌轨与插件外挂字幕都要能选、能关。验证并修好外挂 SRT/VTT/ASS 出 Cue 的路径。

### G4 弹幕
- 数据源两个：
  1. 插件 `danmaku(ctx, { itemId, fromMs, toMs })`，按时间窗分批取（窗口大小、预取提前量、并发、失败退避照规范；规范没写的自己定并写进回报），seek 后丢弃在途结果；经 `PluginMediaSource` 的正规入口，不绕过集成文档的边界。
  2. 本地旁挂文件：与视频同目录同名的 `.xml`（社区通用的弹幕 XML：`<d p="时间,模式,字号,颜色,…">文本</d>`），本机与 WebDAV 源适用。解析要防超大文件和畸形输入（上限、流式解析、不解析外部实体）。
- 轨道分配、防重叠、密度上限、显示区域、速度、字号、不透明度、屏蔽类型照 §6.10。分配器是纯逻辑：给定弹幕序列、设置、时钟，输出每条的轨道、深度层、起止时间；必须确定性（同一输入同一输出），seek、暂停、倍速、改设置后的行为各有测试。
- 渲染：每条弹幕文字画一次进图集，之后每帧只在 GPU 上摆放，不逐帧上传位图。左右眼各一层，每条弹幕按自己的深度产生视差；曲面屏上沿同轴柱面走。图集的容量、淘汰、超长文本截断照规范。
- 漂浮感与层次照 §6.10「分层漂浮」，包括上限（不超过 1.0°、不近于 1.6 m）。
- 「自动」漂浮感所需的深度读回（§7：GPU 直方图 + PBO 异步读回）放在这一阶段最后做；做不到规范要求的开销时，退回固定值方案并在回报里给出测得的数据，**不要**为了它拖慢播放帧率。
- 控制条上的一键开关；没有弹幕来源时调色板弹幕页按规范显示不可用及原因。
- `plugins/reference` 增加 `danmaku` 能力的固定数据，供一致性测试和无第三方插件时的手动验证。

## 硬性约束

- **图层**：任何状态不超过规范 §6.5 的层数；总数永远不超过 16。按 §6.5 的表写一个测试或调试断言，逐状态核对实际提交的层数。
- **帧率**：播放 72/90 Hz 下不得因本任务新增掉帧。渲染线程每帧不做分配、不做 JNI 回调 Java 的同步等待、不做整图上传（内容变化的那一帧除外）。弹幕 150 条同屏时的每帧 CPU 耗时在回报里给出估算依据。
- **输入**：PC 串流场景的输入行为不变；手势追踪可用性不回退。
- **设置持久化**：键名、默认值照 §3.8/§6.3「存在哪里」；旧的 `seekbar_vr_curvature` 等要迁移，不丢用户现有屏幕位姿。
- 设备相关、纸面上定不了的数值（挂载偏移与倾角、350 ms、振动强度、漂浮感默认值）集中成一组常量并注明「待头显验证」，方便之后调。

## 测试

- 上面各阶段点名的纯逻辑测试：输入判定表、调色板状态机、弹幕分配器（含确定性与 seek）、弹幕 XML 解析（畸形/超大/实体）、Cue→排版、设置迁移、图层计数。
- C 侧新增的几何（同轴柱面上的弹幕位置、按深度的每眼偏移）要有主机端可跑的单元测试或与 Java 侧对照的测试向量。
- App 现有测试全部通过，连续跑两遍；`./gradlew :app:assembleNonRootDebug` 通过（含 NDK 编译，无新增警告）。

## 规则

- 可改：`player/`、`plugins/reference/`、必要的文档（`README.md` 的操作说明、`docs/specs/plugin-protocol.md` 若弹幕取数细节需要补充）。不改 `design-opus/`、`host/`、`plugins/jellyfin/`、`tools/plugin-kit/` 的行为。
- 不碰 adb 和头显，不安装 APK，不 push。
- 按 G1→G4 顺序做，每阶段构建和测试通过后提交（英文说明）。G1 做完先停下来回报一次（它最小，头显上要先验证手感），收到继续的指示后再做 G2–G4。
- 回报用中文：每阶段改了哪些文件、关键决定、规范里做不到或有矛盾的条目、所有「待头显验证」的常量清单、测试数量、性能估算依据。逐条写实际状态，不要写「全部完成」这类总括。
