# 任务 H：跨播放源聚合搜索

状态：待实现。设计以 `design-opus/ux-spec.md` §3.9（及 §2.1、§3.8「记住搜索记录」、§7 Compose 落地说明、§8 第 23–26 行）和 `design-opus/mockups/search.html` 的 8 个状态为准；本文只补充工程约束。两者冲突时以设计为准，并在汇报里指出。

## 背景

- 插件协议已有 `search(ctx, { query, cursor?, kind? }): Page<Item>` 与可选的 `suggest(ctx, { query }): string[]`（`docs/specs/plugin-protocol.md`），运行时已实现（`PluginSearchCapability`，`local/plugin/PluginMediaSource.kt`）。Jellyfin、参考插件及第三方插件都已声明 `search` 能力。
- App 没有搜索界面，也没有聚合层。顶栏右上角设计里有放大镜入口，目前未实现。

## 范围

1. **聚合层**（纯 Kotlin，可单测，不依赖 Compose）
   - 输入：查询词、类型筛选；输出：按播放源排列的行状态流（等待中 / 有结果 / 无结果 / 失败 / 需要登录 / 已放弃）。
   - 只查询声明了 `search` 能力且已启用的插件实例；WebDAV / DLNA / 本地文件夹不参与（它们没有搜索接口，统一媒体库另行立项）。
   - 每个源独立并发、独立超时、独立失败；一个源抛错、超时、被取消都不得影响其他源。并发上限与单源超时用常量集中定义，默认按设计（300 ms 首次落版、10 s 放弃）。
   - 行顺序规则按设计：首次落版按播放源固定顺序，之后到达的只追加在末尾，已显示的行不移动、不重排。把这条做成聚合层的不变量并用测试锁定。
   - 新查询必须取消上一轮所有在途请求；迟到的旧结果不得写入新一轮状态（用代次号校验）。
   - 分页：展开单个源后按 `cursor` 追加，去重 item id，分页失败只影响该源、可重试。
   - 类型筛选传给插件的 `kind`；插件忽略 `kind` 时在本地再过滤一次。
   - 联想词：输入时防抖后向支持 `suggest` 的源请求，合并去重、限量；任何源的联想失败都静默。未实现 `suggest` 的插件不得因此报错或刷日志。
   - 需要登录：沿用现有的登录失效判定（与首页货架同一套错误呈现逻辑 `rememberErrorPresentation` 所依据的分类），不要另造。
2. **搜索记录**
   - 仅存本机，条数上限、去重置顶、可逐条删除与全部清除；设置里「记住搜索记录」关闭时不写入并清空已有记录。
   - 不记录到日志；诊断输出里查询词脱敏。
3. **界面**（`local/wall/`）
   - 顶栏放大镜入口、搜索页 8 个状态、类型筛选、展开单源网格、联想词、记录与「最近看过 / 最近添加」（复用首页已有数据来源，不新增网络请求类型）。
   - 文本输入默认用头显系统键盘；与任务 F（头显内输入）共用同一套输入组件，如 F 尚未合并则用现有文本输入组件并留好替换点。
   - 条目激活沿用现有导航规则（电影/剧集进详情，单集进所属剧集并定位，普通视频直接播，文件夹进媒体库）。
   - 列表键必须唯一（源实例 id + 序号 + item id），参考 `HomeScreen.kt` 的处理；任何源返回重复 id 都不能崩溃。
   - 封面走现有 `ArtBox` / `PluginImages` 路径，不新增图片加载方式。
   - 所有文案进 `strings` 资源，中英文齐全。
4. **插件侧**
   - `tools/plugin-kit` 的 `check` 对声明 `search` 的插件做基本校验（空查询、分页游标、`kind` 可忽略）；`docs/plugin-dev.md` 增加「搜索」一节：返回什么、排序由插件自己决定、超时预算、`suggest` 可选、`kind` 可忽略、未登录时抛什么错。
   - 参考插件与 Jellyfin 插件按文档自查并补齐。

## 不做

- 不合并不同源的同名条目，不做跨源相关度排序。
- 不做语音输入（等确认 PICO 是否提供系统语音输入）。
- 不给没有搜索接口的源建本地索引。

## 质量要求

- 遵守 `docs/specs/00-quality-bar.md`。
- 单元测试至少覆盖：行顺序不变量（多种到达顺序）、单源失败/超时/需要登录、取消与代次（迟到结果被丢弃）、分页去重与失败重试、`kind` 本地过滤、联想合并去重与静默失败、搜索记录的上限/去重/关闭即清空、重复 id 不崩溃。
- 不碰 adb / 头显，不 push，只在本分支提交。完成后连续两遍全量测试并汇报实际数字、与设计不一致之处、需要头显验证的清单。
