# depth3d Host ⇄ 头显 约定（v1）

## 发现
Host 在局域网用 mDNS 广播 `_depth3d-host._tcp`，端口为 Host 控制接口的 HTTPS 端口。TXT 记录：

| 键 | 值 |
|---|---|
| `v` | `1` |
| `name` | 显示给用户的电脑名 |
| `id` | 稳定的主机 id（首次启动生成的 UUID） |
| `pair` | `auto`（支持免 PIN 配对） |
| `media` | 媒体服务（WebDAV）端口；没开启时不带这个键 |
| `mrev` | 媒体凭据版本号（从 `1` 开始递增的十进制整数）；每次移除已配对设备并轮换 WebDAV 凭据时加 1。媒体服务未开启或尚未轮换过时可省略；这个值只在 Host 本次运行期间有意义（重启后重新计数，可能重复）；已配对头显监听到 `mrev` 变化（或访问 WebDAV 收到 `401`）时，重新调用 `GET /depth3d/v1/media` 拉取最新凭据 |
| `gs` | 内置串流服务的 GameStream HTTP 端口（默认 47989）；串流引擎未就绪（端口冲突、暂停、异常）时不带这个键 |

内置串流服务仍按标准方式（`_nvstream._tcp`）被发现，头显用地址 + `gs` 端口把两条记录合并成一台电脑。Host 不向局域网广播 `_webdav._tcp`；已配对头显统一通过 `/depth3d/v1/media` 获取媒体服务端口与凭据。

## 控制接口
HTTPS（TLS 1.2），自签名证书。服务端启用**可选**的 TLS 客户端认证：不带客户端证书也能连；带了就校验握手签名（证明持有私钥）。头显的客户端证书就是它用于串流配对的那一张，Host 以它的 SHA-256 指纹作为头显的身份，`deviceId` 只是显示和查找用的标签，不是凭据。

头显与 Host 的全部连接（控制接口和串流配对）使用同一个 IPv4 地址。

### 头显如何信任 Host
- 发现和 `/info` 探测阶段不保存任何东西。
- Host 的证书指纹只在一次配对**完整成功**后保存（连同对应的串流服务端证书）。之后指纹变了要提示用户，用户确认后必须重新走完整配对才更新。
- 没有保存信任的 Host，头显不向它发 `/media`，不采信它给的任何凭据。

### 接口
- `GET /depth3d/v1/info` → `{"v":1,"name":"…","id":"…","os":"macOS 15.1","stream":{"ready":true,"reason":null},"media":{"port":8890}|null}`。`stream.ready=false` 时 `reason` 是给用户看的中文短句。

- `POST /depth3d/v1/pair`，请求体 `{"device":"<头显名>","deviceId":"<id>","pin":"1234","streamPaired":true|false}`。头显**总是带上客户端证书**（证书本身是公开信息；没有证书的请求返回 `401 {"error":"client_cert_required"}`）。`streamPaired` 为 `true` 表示头显本地有这台电脑的串流配对，并且刚刚用已保存的串流服务端证书验证过对方（见「升级路径」）；其余情况一律 `false`。这一步只做「让电脑这边同意」，**不等待串流配对**：
  - 需要用户确认时，Host 弹出不抢焦点的确认窗（显示名字和来源 IP，默认不勾「以后自动允许」）。关闭窗口等于拒绝。
  - 免确认的唯一条件：请求带了客户端证书，其指纹已绑定且那条记录勾了「以后自动允许」。
  - 应答：
    - `200 {"ok":true,"next":"gamestream","ticket":"<不透明串>"}`：已同意，需要做串流配对。应答之前 Host 先做两件事：取消该 IP 在引擎里遗留的待配对会话；删除引擎已配对列表里使用这张证书的**所有**条目（引擎不去重，同一张证书再配一次会产生重复条目并被引擎拒绝）。然后在接下来 60 秒内，把这个 PIN 提交给来自同一 IP 的串流配对会话（会话出现时提交；同一 IP 有多个待配对会话时都拒绝）。头显收到后**才**开始标准串流配对，用同一个 PIN。
    - `200 {"ok":true,"next":"done","ticket":"…"}`：仅当 `streamPaired` 为 `true` 且这张证书在引擎已配对列表里（有重复时 Host 先只保留最新一条，并确保启用）。不需要再做串流配对，头显直接进入 `/pair/complete`。`streamPaired` 为 `false`，或证书不在引擎里，一律走 `gamestream`。
    - `403 {"error":"rejected"}`、`408 {"error":"timeout"}`（60 秒没人点）、`429 {"error":"busy"|"cooldown","retryAfterSec":n}`（已有确认窗，或该来源 IP 刚被拒绝/超时，冷却 30 秒；冷却只按 IP 记）、`503 {"error":"stream_not_ready","reason":"<中文>"}`、`400`（请求体不对）。
  - 这个请求最长阻塞约 60 秒，头显的读超时不得短于 75 秒。请求的连接在确认窗还开着时断开（头显取消或超时），Host 立即关闭确认窗，按取消处理，不发 ticket。
  - ticket 绑定来源 IP 和本次请求的证书指纹，只能用一次。
  - 身份变化：`deviceId` 已有绑定指纹，但本次证书指纹不同 → 当作新设备，确认窗写明「这台设备的身份变了」。同意后**新建**一条记录，不覆盖、不继承原记录的任何状态；原记录保持不变，由用户自己决定是否移除。

- `POST /depth3d/v1/pair/complete`，请求体 `{"ticket":"…","deviceId":"<id>","device":"<头显名>"}`，**必须带客户端证书**。头显在串流配对成功后（或 `next` 为 `done` 时立即）调用：
  - Host 核对：`ticket` 有效且未过期（发出后 120 秒）、来自同一 IP；握手里的客户端证书指纹在串流引擎的已配对列表里且启用。同一张证书在引擎里有多条时，Host 只保留最新一条并删除其余（否则引擎会拒绝这张证书）。
  - 通过后 Host 才保存设备记录（指纹、名字、是否自动允许），应答 `200 {"ok":true,"media":{"port":8890}|null}`。头显收到这个 `200` 后才保存对 Host 的信任，然后可以调用 `/media`。
  - `409 {"error":"not_paired"}`：引擎里还没有这张证书（头显可在 5 秒内重试几次）；`401`：没带证书；`410`：ticket 无效或过期；`403`：来源不符。
  - 任何失败、拒绝或超时，Host 都要取消该 IP 在引擎里的待配对会话，保证头显立刻重试不会遇到「正在配对」。

- `GET /depth3d/v1/media` → `{"webdav":{"port":8890,"user":"…","pass":"…"}}`；媒体服务没开启时 `{"webdav":null}`。必须带客户端证书；指纹必须对应一条已保存的设备记录，并且此刻仍在引擎已配对列表里（启用、唯一）。否则 `401`。`X-Depth3d-Device` 请求头可带可不带，Host 不依赖它。

### 已经在串流层面配过对的头显（升级路径）
头显有这台电脑的串流配对（保存了它的串流服务端证书），但没有对 Host 的信任时：
1. 头显先用已保存的串流服务端证书，对同一地址的串流 HTTPS 端口做一次带证书校验的请求，确认对方就是那台已配对的电脑。不通过则以 `streamPaired: false` 走完整配对（头显丢弃旧的串流配对记录前，如果服务端证书与已保存的不同，要先让用户确认「这台电脑的身份变了」）。
2. 通过后，以 `streamPaired: true` 调用 `/pair`。Host 弹确认窗（这台头显在 Host 这边还没有记录），同意后应答 `next: "done"`。
3. 头显调用 `/pair/complete`，成功后保存信任，同步 `/media`。
整个过程用户只需要在电脑上点一次允许，不需要先在头显上移除电脑。

### 移除设备
Host 移除一台设备时：删除引擎里所有使用该指纹的条目、删除设备记录、轮换 WebDAV 凭据并更新 `mrev`。没有指纹的旧记录直接删除。

### 媒体凭据更新
已配对头显在 WebDAV 返回 `401` 或 `mrev` 变化时重新调用 `/media`。

版本不兼容时任何接口都可以返回 `426`，头显提示「请更新电脑上的 depth3d Host」。
