# design-opus：depth3d 头显界面设计

这是 depth3d（PICO 4 上的 2D 转实时 3D 影院）头显界面的一套独立设计。它从头做起，没有参考仓库里已有的 `design/` 目录。这一轮只出设计，不改 App 代码。

## 怎么看

- 用浏览器直接打开 `mockups/index.html`，不需要服务器，也不联网。每个 HTML 都是自包含的：CSS、图标和状态切换脚本全部内联，没有任何外部 URL。
- 每页底部是状态切换条，右下角的注释写着这个状态为什么这样做。也可以用地址里的 `#状态名` 直接打开某个状态，例如 `mockups/vr-player.html#paused`。
- 2D 面板页画的是一个 1280 × 720 的窗口，浮在模拟的透视房间里；VR 播放页画的是头显视野本身（80° × 50°，1° = 20 px）。画面、海报和背景图全部是色块和渐变，不涉及真实片子或品牌。
- 按 1600 × 1000 的窗口设计，这也是截图自检用的尺寸。

## 修改设计稿

HTML 是生成出来的，不要手改。改 `src/` 里的文件，然后运行：

```
python3 design-opus/src/build.py
```

| 文件 | 内容 |
|---|---|
| `base.css` | token（颜色、字号、间距、圆角、动效）和所有共用组件 |
| `lib.py` | 图标、色块场景、面板外壳、状态切换脚本 |
| `pages.py` | 8 个 2D 面板页 |
| `search.py` | 搜索页（系统键盘画在面板外面，见 `lib.panel_page` 的 `outside`） |
| `vr.py` | VR 播放页 |
| `palette.py` | VR 调色板与弹幕页（复用 `vr.py` 的画面、控制条和射线） |
| `build.py` | 写出全部页面和 index |

## 关键决定

1. **按视角定尺寸。** PICO 4 名义上约 20.6 PPD，设计按有效 18 PPD 算。假设面板宽 53°，1° ≈ 24 px。由此定出最小字 24 px（1.0°）、正文 28 px、最小目标 60 px（2.5°）、线宽至少 2 px。面板的真实尺寸要在头显上量，不对就整体缩放（`ux-spec.md` §1、§8）。
2. **控制条离开画面平面，只用一张贴图。** 控制条 40° × 5.6°，距眼 1.4 m，在画面下方，不挡画面，也不会和 2D 转 3D 后凸出的内容打架。退出键、播放键、片名、进度条、时间、「弹」和「调整」都画在一张贴图里。加上弹幕和调色板，任何状态最多 13 层（上限 16）。现在的实现是药丸加 7 个按钮，要 14–17 层（§6.5、§6.8）。
3. **低频设置放进左手的调色板。** 调色板取代了快捷菜单。
   - 尺寸：20 × 15 cm，贴图 1024 × 768，挂在左手握把上方，距眼 35–55 cm。
   - 内容：4 个标签（3D / 屏幕 / 弹幕 / 字幕音轨），每页最多 4 行，行高 2.81 cm。
   - 操作：右手射线指行，右手摇杆左右改值（一格一振），按下摇杆复位。左手摇杆切标签，≡ 开关，图钉把它留在空中。
   - 保存：强度、片源、字幕轨、音轨跟着片子存，其余是和设置页同一份的全局值（§6.3）。
4. **不用键盘。** 依次靠局域网自动发现、手机扫码填写、Jellyfin 快速连接码、数字 PIN，系统键盘最后才用（§4.6）。
5. **克制的视觉。** 暗色分层底，每屏最多一个白色主按钮，琥珀色只用于进度和「已开启」，渐变只用作图片遮罩。正常的东西不标状态，只有出问题的地方说话（§0、§5）。
6. **弹幕是播放页的主角之一。**
   - 默认上半屏 7 条轨道，字号 1.4°，8 s 横穿，80% 不透明。
   - 用左右眼各一层画，每条弹幕按轨道分到远、中、近三层，深度用视差记。默认远层在画面最靠前的内容前 0.10°，三层跨度 0.30°；上限 1.0° 且不近于 1.6 m，永远在控制条后面。
   - 每条弹幕从出现到离开深度不变，所以不晕。
   - 图集渲染，出现后不再改（§6.10）。
7. **按住扳机推摇杆调整屏幕。**
   - 前后是远近，左右是大小，经过档位有吸附和振动，读数形如「3.4 m · 中 50° · 143 寸」，松开保存，B 撤销。
   - 和单击暂停靠 350 ms 与摇杆阈值区分；按在控件上永远是点控件（§6.4、§6.12）。
   - 曲度从开关变成 0–100% 的连续值。弹幕和字幕默认和画面同轴（§6.12）。

8. **搜索按播放源分行，结果只往下加。**
   - 不做合并的「最佳匹配」行，同名片子也不合并：各源的分数不能比较，合并就要在射线底下改已经显示的东西。
   - 300 ms 时先到的按播放源顺序排好，之后到的只接在最后；10 s 没回来的源变成一行「重试」。
   - 进来不弹键盘，先给搜索记录和最近看过；打字时只联想，按「搜索」才去问播放源（§3.9）。

## 取舍

- **悬停不切换内容。** 媒体库左栏悬停时右栏不变，要点一下才切换。这样多了一次点击，但射线扫过时界面不会乱跳。
- **控制条只留 4 个东西（有弹幕时多一个「弹」）。** 环境、3D、屏幕要抬左手或点「调整」才能改。换来的是常驻界面更少，图层也更省。
- **投屏不自动打断看片。** 即使是已经允许过的设备，看片时投屏也要确认。代价是多一步，但正在看的片子不会被别人的手机切走。
- **不做射线停在边缘自动滚动，也不做整页横移动画。** 都是为了避免让人感觉自己在动。
- **调色板每页最多 4 行。** 弹幕要分两页，密度、合并重复、弹幕曲度和字幕曲度只能进设置页。换来的是两只手都在抖时也点得准。
- **漂浮感和层次放在 3D 页，不放在弹幕页。** 它们是纵深，和强度联动，而且字幕也用。代价是调弹幕深度要切一次标签。
- **弹幕不做近快远慢。** 分层只靠视差，所有层同速。少了一点「层次感」，换来不违反「不做视差动画」，也不晕。
- **手上的调色板不推字幕，钉住的才推。** 手一直在动，字幕跟着跳比被挡一下更糟。
- **去掉了「摇杆上下改 3D 强度」和「重新放到正前方」。** 前者和调整屏幕抢同一根轴；后者和长按 PICO 键重复。
- **搜索结果按到达顺序排，不按相关度排。** 慢的源即使更相关也排在后面，换来的是已经显示的行永远不动。
- **打字时不实时搜。** 要多按一下「搜索」，但不会把半个词发给所有插件，结果也不会在射线底下换来换去。
- **出问题的源一行带过。** 登录和重试都在那一行里完成，不弹窗；代价是需要登录的源在第一次搜之前看不到任何结果。
- **调整屏幕时向前推 = 推远。** 像把屏幕推出去；也有人会觉得「向前 = 靠近」，留给实测。

## 还没想清楚的问题

1. PICO 2D 窗口的真实物理尺寸和 dp 密度。整套尺寸都建立在「面板 53°、1° ≈ 24 px」这个假设上。
2. Host 下载地址。`depth3d.app/mac` 只是占位，域名还没定。
3. 投屏确认里「以后自动允许这台设备」默认开还是关。默认开更省事，默认关更安全。
4. 手势射线抖动和捏合漂移的真实数值。80 ms 回溯和 1.5° 拖动阈值都是估计值。
5. 控制条整张贴图重画的延迟。如果悬停反馈超过 2 帧，悬停高亮可能要拆成单独的小层。
6. 漂浮感的默认值（远层在内容前 0.10°、层次 0.30°）舒不舒服，深度读回的噪声会不会让新弹幕忽前忽后。原生 3D 片源没有深度图时按 0.25° 是否够用。
7. PICO 透视模式下能不能叠半透明调暗层。不能的话，「调暗房间」只能在影院房间环境里做。
8. 调色板挂在手上的数值（握把上方 8 cm、后仰 40°、修正 20°）和两手同时抖时 2.5 cm 的目标够不够。
9. 默认屏幕距离（3 m）和控制条距离（1.4 m）的聚散舒适度，要看完一部片子再评。
10. 单击和按住调整的阈值（350 ms、死区 0.25、阈值 0.5）会不会误判；扳机按住要不要也能拖位置。
11. 1.4° 的移动弹幕读不读得清；两侧 1.5° 羽化有没有用。
12. 柱面层能不能用在分眼的弹幕层上；影院房间里要不要也让画面弯。
13. 每帧画两张最宽 2048 的弹幕贴图，GPU 还剩不剩给 2D 转 3D。
14. 去掉「重新放到正前方」以后，用户找不找得到长按 PICO 键。
15. 设置页画稿还没跟上这一轮的变化（也还没有「隐私 › 记住搜索记录」）。
16. PICO 系统键盘浮在哪里、挡住面板多少。搜索页按「面板 y 0–440 是安全区」设计（`ux-spec.md` §3.9.6、§8 #23）。
17. 插件的搜索接口要能声明「能搜索」「能给联想」「能按类型筛」「要登录」。这是插件 API 的事，设计只假设有这几个开关。
18. 同名片子不合并，以后要不要在详情页写「另外 2 个播放源也有」。
