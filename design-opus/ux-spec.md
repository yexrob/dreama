# depth3d 头显界面规范（design-opus）

适用设备：PICO 4（XR2 Gen 1，单眼 2160×2160，水平视场约 105°），也要能在 Quest 系列上跑。
两个界面面：

- **2D 面板**：一个 Compose Activity，用射线加扳机或捏合操作，基本不打字。
- **VR 场景内界面**：播放时的 OpenXR quad 图层，每帧最多 16 层。

配套设计稿在 `mockups/`，打开 `mockups/index.html` 看总览。每页底部能切换状态，右下角的注释写着这个状态为什么这样做。本文是完整的理由和数值。

文中的 **px** 有两种用法。2D 面板里指 1280×720 设计画布上的像素；VR 播放页里，1° = 20 px，只是作图比例。凡是用来做决定的数，都换算成**视角（°）**。

---

## 0 原则

1. **画面是主角，界面退后。** 背景图和视频占满，界面用深色半透明底。整页最多一个白色主按钮，强调色只用在进度和「已开启」上。参照的是 Apple TV app 和 Infuse 的克制：没有渐变按钮、霓虹描边或玻璃拟态。
2. **按视角定尺寸，不按像素定。** 字号、目标和线宽先从头显的角分辨率推出来，再落到 px（见 §1）。
3. **正常不出声，出问题才说话。** 连得上的播放源不标「已连接」，只有连不上的那一行变红，并给一个动作。
4. **能不打字就不打字。** 依次靠自动发现、扫码在手机上填、Jellyfin 快速连接码、数字 PIN，系统键盘放在最后（§4.6）。
5. **射线经过时界面不乱动。** 悬停只做放大和提亮，不切换内容、不展开、不自动滚动。要改变内容必须点一下。
6. **播放时图层要省。** 一个控件不单独占一层，整条控制条只用一张贴图。全场景最多 11 层，留 5 层余量（§6.5）。

## 1 尺寸推导

### 1.1 头显能分辨多细

| 量 | 值 | 来源或理由 |
|---|---|---|
| 单眼分辨率 | 2160 × 2160 | PICO 4 规格 |
| 水平视场 | ≈ 105° | PICO 4 规格 |
| 名义角分辨率 | 2160 / 105 ≈ **20.6 PPD** | 平均值，镜片中心略高、边缘更低 |
| 设计用有效 PPD | **18 PPD** | 合成器对 quad 层重采样、镜片边缘衰减、头部微动造成的模糊都会损失清晰度，所以按 ~85% 打折 |

结论：**1° 约等于 18 个可分辨的屏幕像素**。设计稿里任何小于约 1.5 个屏幕像素的东西都会闪烁或消失。

### 1.2 2D 面板

- **假设**：面板显示为 1.6 m 宽，距离眼睛 1.6 m，即 2·atan(0.8/1.6) ≈ **53.1°**。设计画布是 1280×720，所以 **1° ≈ 24.1 px**。
- 一个设计 px 约等于 18 / 24 = **0.75 个屏幕像素**，比手机密得多。由此：
  - **线宽至少 2 px**（0.083°，约 1.5 个屏幕像素）。1 px 的分隔线会抖动，所以本设计不用分隔线，改用间距和底色区分层级。
  - 图标描边 2.2 px（28 px 图标），不用 1.5 px 以下的细线图标。
- 面板的实际物理尺寸由 PICO 系统决定，见 §8。数值不对时整套 token 按比例缩放，比例关系不变。

### 1.3 字号

汉字笔画密，要可靠分辨「赢」「餐」这类字，字高至少需要约 16–18 个屏幕像素。按 18 PPD 计算，**1.0° 是下限**。

| 角色 | px | 视角 | 屏幕像素 | 字重 | 行高 |
|---|---|---|---|---|---|
| display（片名） | 64 | 2.7° | 48 | 600 | 1.1 |
| title（页标题） | 44 | 1.8° | 33 | 600 | 1.2 |
| head（区块标题、弹层标题） | 32 | 1.33° | 24 | 600 | 1.3 |
| body（正文、列表主文字） | 28 | 1.17° | 21 | 400 / 500 | 1.5 |
| caption（次要信息、元数据） | **24** | **1.0°** | 18 | 500 | 1.4 |

- 不用 300 及以下的字重：细笔画在低 PPD 下会断。caption 用 500 补偿。
- 不用负字距。数字统一用等宽数字（`tabular-nums`），这样时间跳动时不会左右抖。
- 一行最多约 28 个汉字（正文 28 px × 28 ≈ 784 px ≈ 33°）。超过这个宽度眼睛要转头去找行首。

### 1.4 目标尺寸

射线的抖动来源有三个：

- 手柄射线静止时的抖动，约 0.3–0.6°。
- 手势射线更大，约 1°。
- 捏合瞬间手指带着射线往下漂，约 1–2°。

| 角色 | px | 视角 | 理由 |
|---|---|---|---|
| 最小目标（次要按钮、分段选项） | **60** | 2.5° | 抖动 ±1° 时仍有 0.25° 余量 |
| 主要目标（主按钮、圆形图标按钮） | **64** | 2.7° | |
| 列表行 | 88 高，整行可点 | 3.65° | 行内只放一个主要动作 |
| 目标之间的空隙 | **≥ 16** | 0.67° | 加上 §4.2 的悬停滞回，防止在边界来回跳 |

### 1.5 对比度

在面板底色 `#0E0F12` 上：

| 前景 | 对比度 | 用途 |
|---|---|---|
| text `#ECECEE` | 16.2 : 1 | 主文字 |
| text-2 `#A6A9B0` | 8.1 : 1 | 次要文字（在 surface-hi 上仍有 6.7 : 1） |
| text-3 `#7D818A` | 4.9 : 1 | **只用于禁用态** |
| accent `#E3A857` | 9.1 : 1 | 进度、已开启 |
| danger `#EE8577` | 7.5 : 1 | 连不上、出错 |

- 次要文字定在 ≥ 7 : 1，比 WCAG AA 的 4.5 高。头显里的对比度会被镜片眩光和合成器模糊吃掉一截，要留余量。
- 纯白 `#FFF` 只在悬停的主按钮上出现。常态主文字用 `#ECECEE`，避免大面积纯白在 OLED 风格的黑底上产生光晕。

### 1.6 VR 场景内

| 量 | 值 | 理由 |
|---|---|---|
| 作图比例 | 1° = 20 px | 只是画图用 |
| 贴图密度 | **40 texel/°** | 约为有效 PPD 的 2 倍，配合 mipmap，头动时文字不闪。再高只是浪费显存和带宽 |
| 最小字 | 22 px = **1.1°** | 比面板的 1.0° 高一点，因为控制条在视线下方 15–21°，那里镜片更糊 |
| 最小目标 | 50 px = **2.5°** | 和面板一致 |
| 播放键 | 64 px = **3.2°** | 播放中最常点的东西 |
| 进度条 | 视觉 0.3° 粗，悬停 0.5°；命中区 **2.5° 高** | 细线好看，命中区要宽 |
| 控制条 | 40° × 5.6°，贴图 1600 × 224 | 只有一张贴图 |
| 快捷菜单 | 26° × 13.4°，贴图 1040 × 536 | |

### 1.7 到头显上必须核对的

面板的真实物理尺寸和 dp 密度、合成器对 quad 层的实际锐度、手势射线的实际抖动，全部列在 §8。

## 2 信息架构与导航

### 2.1 结构

```
顶部导航（常驻）：首页 · 媒体库 · 投屏                         搜索  设置
│
├─ 首页          继续观看 → 每个播放源一行（最近添加 / 电影 / 剧集…）
│   └─ 详情页（电影 / 剧集）→ 播放（VR）
├─ 媒体库        左：所有播放源   右：选中源的分类
│   ├─ 分类网格 → 详情页 → 播放
│   └─ 管理播放源（播放源与插件）→ 添加播放源 → 用手机输入
├─ 投屏          等待投屏（设备名）+ 电脑串流（Mac / PC）
│   └─ 电脑配对（PIN）
├─ 搜索          （跨所有播放源）
└─ 设置          左栏分类，右栏选项
```

- **只有 3 个一级标签。** 头显里每多一个标签，射线就要多扫一段。设置和搜索是工具，不是目的地，所以放在右上角，做成图标。
- **最深 3 层**（标签 → 列表 → 详情）。推入的页面左上角有圆形返回键，手柄 B 键或系统返回手势也能返回。不做面包屑。
- 标签切换不加横向滑动动画，直接淡入淡出（§5.6）。大面积横移会让人产生自身在动的错觉（vection）。

### 2.2 投屏和串流放在哪里

| 能力 | 方向 | 入口 | 理由 |
|---|---|---|---|
| AirPlay 镜像、DLNA 投送 | 别的设备推过来 | 「投屏」标签只负责**显示设备名并等待**；接收服务只要 App 开着就在后台运行 | 用户真正的操作在 iPad 或手机上，头显这边只需要让对方找得到这个名字 |
| 投屏请求 | 推过来 | 在**任何页面**弹出确认（2D 面板用弹层，播放中用卡片） | 不能要求用户先切到「投屏」页才能接收 |
| Moonlight 串流（Mac / PC） | 头显主动去连 | 「投屏」页下半部分的「电脑串流」 | 和投屏一样，都是「看另一台设备的画面」，用户心里归为一类 |
| depth3d Host（Mac） | 两种角色 | 在「媒体库」里是一个**播放源**（片库，以及经 Mac 的 rclone WebDAV 访问 Google Drive）；在「投屏 › 电脑串流」里是一台**电脑** | 只配对一次，两处都能用。用户不需要理解 Host 是什么，只要知道「装了它，Mac 上的片子和屏幕都能看」 |

### 2.3 首次使用

首次使用有三步（欢迎 → 片源 → 操作），可以跳过。「片源」一步选了 Mac，才多出一步「装 Host」。只想投屏的人什么都不用选，直接继续。

## 3 页面

每页的布局以 `mockups/*.html` 为准，这里只写**规则**和**状态**。共有规则：页面左右边距 64 px；区块标题 32 px；海报行横向滚动，行首和页边距对齐。

### 3.1 首页播放墙（home.html）

| 状态 | 规则 |
|---|---|
| 默认 | 第一屏：上次看的片子做主角（背景图加左侧和底部的遮罩），一个白色「继续播放」加一个「详情」。下面一行「继续观看」，卡片 16:9、264 px 宽，进度条 6 px 高，用强调色。悬停：卡片放大 6%，中间出现播放符号，**点卡片直接续播**，不进详情 |
| 向下滚动 | 英雄区收起，导航从透明改成实底。每个播放源一行海报（168×252），行标题带「›」，可点，进入该分类 |
| 没有播放源 | 标题「还没有可以看的片子」，下面三张卡：局域网里已经发现的服务器（排第一，点一下就加）、头显里的视频、投屏（不用设置）。底部一个文字按钮引导装 Mac Host |
| 加载中 | **超过 300 ms 才出骨架。** 骨架和真实布局同尺寸，只做 1.6 s 的明暗呼吸，不做横扫高光（大面积移动的高光在头显里很晃眼） |
| 一个源连不上 | 只有那一行说话：显示缓存内容并压暗，行标题旁加红色的「连不上 NAS，下面是 2 小时前的内容」和「重试」。其他行照常 |

### 3.2 媒体库（library.html）

| 状态 | 规则 |
|---|---|
| 播放源与分类 | 左栏 392 px 列出所有播放源（图标、名称、一行说明），右栏是选中源的分类方块（3 列）。**悬停不切换右栏，必须点一下**，免得射线扫过左栏时右边跟着乱跳。左栏底部是「管理播放源」 |
| 分类网格 | 6 列海报（172×258），海报上本身印着片名，网格下面不再重复写。右上角只有一个排序按钮（最近添加 / 名称 / 年份） |
| 源连不上 | 右栏换成：红色图标、「连不上『旧电脑共享』」、可能的原因、上次连上的时间、「重试」（主按钮）和「检查设置」。不显示错误代码，代码记在日志里 |

### 3.3 电影详情（movie.html）

| 状态 | 规则 |
|---|---|
| 默认 | 背景图是主角，界面退后。片名 64 px，元数据一行，简介**最多一行**（头显里不读长文），「继续播放」（白）、「从头播放」、收藏。下面是进度条和「剩余 38 分钟」。底部四个设置块：3D / 字幕 / 音轨 / 版本，字小一级、底色更浅，属于第二层 |
| 3D 设置 | 点「3D」弹出：片源三选一（自动转换 / 原片是左右 3D / 原片是上下 3D），强度四档（关闭 / 柔和 / 标准 / 强烈，「关闭」就是看原始 2D）。改了立即生效，**记在这部片子上**，默认值在设置里。点弹层外面或按返回键关闭 |
| 加载中 | 文字先到（来自列表缓存），背景图后到，淡入 240 ms。点播放后按钮在原地转圈、文字变成「正在准备」，不跳页 |
| 不能播放 | 错误留在原地：主按钮下面一行红字「NAS 没有响应，暂时不能播放」加「重试」。不弹窗，不把用户推到别的页面 |

### 3.4 剧集详情（series.html）

| 状态 | 规则 |
|---|---|
| 默认 | 主按钮直接写会播哪一集：「继续播放 · 第 2 季第 4 集」。选季和导航用同一种标签样式。集卡片：看完的只写「已看完」，看到一半的才有进度条。集列表进页时自动滚到「下一集」，左边留一集已看的作为上下文 |
| 切换季 | 标签立即变，集列表换成同尺寸的骨架，页面其他部分不动 |

### 3.5 播放源与插件（sources.html）

| 状态 | 规则 |
|---|---|
| 播放源 | 列表行 88 px，整行可点，点进去能改地址、账号和在首页的顺序。正常的源不写状态，连不上的写红字 |
| 插件 | 每个插件写明**版本、来源（内置或哪个仓库）、能访问什么**（局域网或哪个域名）。有更新时行尾出一个按钮，平时只有箭头。右上角「添加插件仓库」通过手机输入地址 |
| 添加播放源 | 上半部分是**局域网里找到的**（Bonjour、SSDP、Jellyfin 的 UDP 7359 广播），已经加过的写「已添加」。下半部分是手动类型：本机文件夹 / Jellyfin / Emby / WebDAV / SMB / depth3d Host |
| 用手机输入 | 需要填地址或账号时，**不弹头显键盘**，弹出二维码：手机扫码打开一个局域网网页，填完后头显自动继续。不能扫码时，显示地址和 4 位验证码，手动在手机浏览器里输入。Jellyfin 还可以「改用快速连接码」，在已登录的设备上确认 |

### 3.6 投屏（cast.html）

| 状态 | 规则 |
|---|---|
| 等待投屏 | 这页的主角是**设备名**「客厅的 depth3d」（64 px），因为别的设备上要找的就是这几个字。iPad / iPhone 和手机视频 App 的做法各写一句。下面是「电脑串流」：已配对的 Mac、未配对的 PC、添加电脑 |
| 首次确认 | 陌生设备第一次投屏时，弹层「小林的 iPhone 想投屏到这里」，加一个开关「以后自动允许这台设备」（默认开），按钮「允许」（白）和「拒绝」。**在任何页面都会弹出** |
| 连接中 | 居中：转圈、「正在连接小林的 iPad」、「画面一出来就会自动进入 3D 播放」、「取消」。连上后直接进 VR 播放，不需要再点 |
| 电脑配对 | Sunshine 需要 PIN：数字放到 88 px、字距加宽，方便对着抄。装了 depth3d Host 的 Mac 自动配对，不需要这一步 |
| 没有网络 | 居中：红色 Wi-Fi 图标、「还没连上 Wi-Fi」、一句原因，只给一个动作「打开 Wi-Fi 设置」 |

### 3.7 首次使用引导（onboarding.html）

| 步骤 | 规则 |
|---|---|
| 1 欢迎 | 只有名字、一句话、一个按钮。插图用三层错开的画面暗示「深度」，不放产品截图 |
| 2 片源 | 三个可多选的大卡片（368×232）。局域网里已经发现的服务器**预先勾上**。「只想投屏？直接继续，不需要设置」 |
| 2b 装 Host | 选了 Mac 才出现。地址短到可以照着敲（`depth3d.app/mac`，域名待定，见 §8），三步说明，底部「正在局域网里找 Mac…」。装好后头显自动发现 |
| 3 操作 | 只教三件事：扳机或捏合、摇杆左右、按住握把。教完就开始看片，其他操作在播放时随用随现 |

### 3.8 设置（settings.html）

左栏分类：播放与 3D / 屏幕与环境 / 投屏 / 手柄与手势 / 播放源 / 隐私 / 关于。右栏是选项。

- 每行 88 px，整行可点。**选项少于 5 个时直接平铺成分段选择**，不用下拉，因为下拉在头显里要点两次，还会遮住别的行。
- 这里改的是**默认值**。播放中在快捷菜单里改的只影响当前这部片子（3D 强度、片源格式、屏幕大小等）。
- 「播放与 3D」：默认 3D 强度、识别原生 3D 片源、深度计算（流畅优先 / 画质优先）、字幕位置、片尾自动播下一集。
- 「屏幕与环境」：默认屏幕大小（小 40° / 中 50° / 大 62° / 巨幕 80°）、默认距离（近 2 m / 中 3 m / 远 5 m）、播放时调暗房间、曲面屏幕、默认环境。
- 「关于」：版本、开源许可（GPLv3）、第三方组件、崩溃报告（**默认关闭**）、检查更新。

### 3.9 搜索（只写规则，没有画稿）

- 跨所有播放源搜索，结果按播放源分组，每组最多一行海报，可以展开。
- 输入方式依次是：系统语音输入（如果 PICO 提供）、系统键盘。还没输入时，页面先显示「最近看过」和「最近添加」，大多数时候不用打字就能找到。

## 4 VR 交互规则（2D 面板和场景内通用）

### 4.1 指向方式

| 输入 | 指 | 选 | 滚动 |
|---|---|---|---|
| 手柄 | 射线 | 扳机（按下再在同一目标上松开） | 摇杆，或者按住扳机拖 |
| 手势 | 手势射线 | 捏合（同上） | 捏住拖动 |

- 点击 = **在同一个目标上按下再松开**。按下后移出目标再松开就算取消，给用户反悔的机会。
- 不用长按：射线状态下长按很难稳住。次要动作都做成看得见的按钮。

### 4.2 悬停与焦点

- 射线进入目标：120 ms 内放大（按钮 1.04，海报和卡片 1.06），底色升一级（`fill` → `fill-hi`）。文字颜色不变。
- **滞回**：射线进入目标的命中框就算悬停；离开时要超出命中框外扩的 8 px（0.33°）才算离开，防止射线压在边界上时闪烁。放大 1.04 后，视觉上也正好覆盖了这一圈。
- 同时只有一个目标处于悬停。没有「键盘焦点环」：头显里没有 Tab 键，焦点就是射线所指。
- 悬停**不改变布局**：不展开、不切换内容、不出提示气泡（进度条的时间气泡是唯一例外，它浮在上方，不占位置）。
- 射线所指的点是一个 18 px 的白点，外加一圈 3 px 的深色描边，在亮的画面和暗的界面上都看得见。

### 4.3 捏合冻结

捏合的那一下，手指会带着射线往下漂 1–2°。规则：

1. 选中判定用**捏合开始前约 80 ms 的射线位置**，而不是捏合那一刻的位置。
2. 捏住期间射线移动不超过 1.5° 时，算一次点击，射线视觉上冻结在原位。
3. 超过 1.5° 就转成拖动或滚动，不再算点击。

80 ms 和 1.5° 都是初始值，要在头显上实测（§8）。

### 4.4 滚动

- 海报行横向滚动，页面纵向滚动。可以用摇杆（每推一下移动一屏的 80%），也可以按住拖（有惯性，最后吸附到卡片边缘）。
- **不做射线停在边缘自动滚动**：在头显里，内容自己移动会让人头晕，也容易误触。
- 滚动时暂停悬停效果，停下 150 ms 后再恢复，免得卡片一路扫过一路放大。

### 4.5 触觉与声音

- 手柄振动：悬停进入时轻触（约 5 ms，强度 0.2），点击约 15 ms、强度 0.5。手势输入没有触觉，只靠视觉。
- 不加界面音效。看片的 App 应该安静。

### 4.6 不用键盘的输入顺序

| 优先级 | 方式 | 用在哪 |
|---|---|---|
| 1 | **自动发现**：Bonjour（mDNS）、SSDP / DLNA、Jellyfin 的 UDP 7359 广播 | 添加播放源、找 Mac Host、首次使用 |
| 2 | **手机扫码**：头显开一个局域网网页（显示地址和 4 位验证码），用手机填 | 服务器地址、账号密码、插件仓库地址 |
| 3 | **Jellyfin 快速连接码**：头显显示 6 位码，在已登录的设备上确认 | Jellyfin 登录 |
| 4 | **数字 PIN**：只有 4 个数字，用数字按钮输入 | Sunshine 配对（头显显示，电脑上输入） |
| 5 | 系统键盘 | 搜索，以及上面都不行的时候 |

## 5 视觉规范

### 5.1 颜色

| token | 值 | 用途 |
|---|---|---|
| `bg` | `#0E0F12` | 面板底色（不用纯黑，纯黑在 LCD 上发灰，还会和房间的透视画面形成刺眼的边缘） |
| `surface` | `#17191D` | 卡片、列表行、骨架 |
| `surface-hi` | `#202328` | 悬停的行 |
| `sheet` | `#1A1C20` | 弹层 |
| `fill` / `fill-hi` | 白 10% / 18% | 次要按钮、悬停 |
| `sel` | 白 20% | 选中的标签和分段 |
| `text` / `text-2` / `text-3` | `#ECECEE` / `#A6A9B0` / `#7D818A` | 主文字 / 次要文字 / 只用于禁用 |
| `accent` | `#E3A857`（琥珀） | **只用于**进度条和「已开启」的开关 |
| `danger` | `#EE8577` | 连不上、出错 |
| 遮罩 | `#08090B` 66% | 弹层背后 |

- 选琥珀不选蓝：蓝色在暗场里像系统控件，在电影画面上很跳；琥珀接近放映厅的暖光，在冷调和暖调的画面上都不突兀。
- **渐变只用作图片上的遮罩**（让文字压得住背景图），不用在按钮或底色上。
- **每屏最多一个白色主按钮**，这样一眼就知道该点哪里。

### 5.2 字号

见 §1.3。中文字体用系统的 Noto Sans CJK / 思源黑体，西文和数字用同一字体，不混排第二种西文字体。

### 5.3 间距

- 8 px 网格。页面左右边距 64 px（2.7°）。
- 区块之间 40–56 px，同一区块内 16–24 px，卡片之间 24 px。
- 海报行的行高要能容下放大 1.06 后的卡片，上下各留 ≥ 16 px，放大时不能被裁切。

### 5.4 圆角

| 元素 | 圆角 |
|---|---|
| 面板、弹层 | 28 px |
| 卡片、按钮、列表行、方块 | 16 px（海报 14 px） |
| 标签、开关、圆形按钮 | 全圆 |
| VR 控制条和菜单 | 24 px（1.2°） |

### 5.5 阴影与层次

层次靠底色深浅（bg → surface → surface-hi → sheet）区分，不靠阴影。阴影只用在两处：浮起的弹层，以及悬停放大的海报（让它从行里浮出来）。

### 5.6 动效

| 场景 | 时长 | 曲线 | 说明 |
|---|---|---|---|
| 悬停（按钮、行） | 120 ms | `cubic-bezier(.2,.8,.2,1)` | 放大 1.04 + 底色 |
| 悬停（海报、卡片） | 140 ms | 同上 | 放大 1.06 + 阴影 |
| 弹层进入 / 退出 | 200 / 140 ms | 同上 | 淡入 + 上移 16 px |
| 页面推入 / 返回 | 220 ms | 同上 | 交叉淡入 + 24 px 位移，**不做整页横移** |
| 标签切换 | 160 ms | 线性 | 只淡入淡出 |
| 骨架 | 1.6 s 一周 | ease-in-out | 延迟 300 ms 才出现 |
| 背景图 | 240 ms | 线性 | 淡入 |
| VR 控制条出现 / 消失 | 180 / 300 ms | | 淡入 + 上移 0.5° / 淡出 |
| 调暗房间 / 开灯 | 600 / 300 ms | | 开始播放时慢慢变暗，暂停时较快亮回来 |

禁止：弹跳、视差、整个面板移动，以及任何让视野大面积运动的效果。

## 6 VR 播放中

画稿：`mockups/vr-player.html`。画稿画的是头显视野（80° × 50°），视线中心在 (800, 500)。

### 6.1 布局

| 元素 | 位置与尺寸 | 理由 |
|---|---|---|
| 画面 | 默认「中」宽 **50°**（16:9 时高 28°），中心在视线水平线上，下沿俯角 14°。距离默认 3 m（2.8 m 宽，约 126 英寸） | 50° 是整幅画面不用转头就能看全的上限。大小按角度定，所以改距离只改变立体纵深，不改变画面看起来多大 |
| 控制条 | **40° × 5.6°**，距眼 **1.4 m**，俯角 15.3°–20.9°，上沿比画面下沿低约 1.3° | 不压在画面上；比画面近，所以 2D 转 3D 后从画面里凸出的东西不会穿过它（避免立体窗口冲突）；1.4 m 在手臂可及范围附近，聚焦舒服 |
| 控制条俯角限制 | **10°–30°** | 画面放大到「巨幕」时，控制条跟着下沉，但不低于 30°（再低就要低头）；画面缩小时不高于 10°（再高就会挡画面） |
| 退出键 | 56 px（2.8°）圆形，在控制条左边，单独浮着 | 和播放键分开，避免误触；离开播放不需要确认，因为进度总会保存 |
| 快捷菜单 | **26° × 13.4°**，从「调整」按钮的正上方长出来，右缘和控制条右缘对齐 | 菜单是控制条的一部分，眼睛不需要跳到别处去找 |
| 字幕 | 在画面内，下沿上方约 2°。**菜单或弹出卡片打开时抬到画面中部**（菜单上方） | 字幕永远不被界面挡住 |
| 提示（toast） | 头部锁定但懒跟随，在视线下方 18°，高 2.6° | 不管看向哪里都看得到；懒跟随（头转动超过 10° 才跟上，有 300 ms 缓动）避免像贴在眼镜上一样晃 |

控制条里有：播放 / 暂停（64 px 白色圆）；片名一行（片名 600 字重 + 「· 年份 · 来自 NAS」用 text-2）；进度条；左边是已播时间，右边是**剩余时间**（带负号）；右端是「调整」药丸按钮（打开快捷菜单）。

### 6.2 出现与消失

| 条件 | 行为 |
|---|---|
| 射线进入画面或控制条 | 控制条淡入（180 ms） |
| 射线离开画面和控制条 **3 s** 后，或射线一直不动 **4 s** | 淡出（300 ms） |
| 暂停 | **常驻**，不隐藏；房间亮回来（调暗层从 58% 降到 14%） |
| 快捷菜单打开 | 控制条**不隐藏**，直到菜单关闭 |
| 什么都不碰 | 只剩画面和字幕。射线和手柄模型也隐藏，碰一下扳机或动一下摇杆再出现 |

### 6.3 快捷菜单

标签：**3D / 屏幕 / 字幕 / 音轨 / 环境**。每个标签最多 3 行，菜单高度固定。

| 标签 | 内容 |
|---|---|
| 3D | 强度（关闭 / 柔和 / 标准 / 强烈）；片源（自动转换 / 左右 3D / 上下 3D）；底注「只对《片名》生效 · 默认值在设置里」 |
| 屏幕 | 大小（小 / 中 / 大 / 巨幕）；距离（近 / 中 / 远）；「重新放到正前方」 |
| 字幕 | 字幕轨（关闭 / 各语言）；字号（小 / 中 / 大）；位置（跟随画面 / 固定在下方） |
| 音轨 | 音轨列表 |
| 环境 | 透视 / 影院房间 / 纯黑；播放时调暗房间（开 / 关） |

- 选项 50 px（2.5°），改了**立即生效**，没有「确定」按钮。
- 关闭菜单：右上角 ×；在菜单外扣扳机（**只关菜单，不暂停**）；按 B；或者再点一次「调整」。
- 选项超过一行时（比如字幕轨很多），那一行改成可以横向拖动的列表，菜单本身不变高。

### 6.4 输入映射

| 输入 | 动作 |
|---|---|
| 扳机 / 捏合（射线在画面上，不在控件上） | 播放 / 暂停。菜单开着时，改为关闭菜单 |
| 扳机 / 捏合（在控件上） | 点那个控件 |
| 扳机（在进度条上） | 跳到那个位置。按住拖动可以连续拖，时间气泡跟着走 |
| A | 播放 / 暂停 |
| 摇杆左 / 右 | −10 s / +10 s。按住 1 s 后变成每次 30 s。同时显示控制条 |
| 摇杆上 / 下 | 3D 强度升 / 降一档，只弹出 toast，不打开任何界面（**暂定**，见 §8） |
| 按住握把 + 移动手柄 | 拖动画面（在以人为中心的球面上移动，距离不变） |
| 按住握把 + 摇杆上 / 下 | 放大 / 缩小画面，经过小 / 中 / 大 / 巨幕时有轻微吸附和振动 |
| 菜单键（≡） | 打开 / 关闭快捷菜单 |
| B | 关闭最上层（菜单、卡片）。没有可关的东西时，第一次按出 toast「再按一次退出播放」，2 s 内再按一次就退出 |
| 手势 | 只有捏合（相当于扳机）。没有摇杆的操作都能通过控制条和菜单完成：拖进度条代替快进快退，在菜单里调强度 |

### 6.5 图层预算

上限 16 层。本设计**全部槽位加起来最多 11 层**，留 5 层余量给系统和以后的功能。

| 槽位 | 层数 | 说明 |
|---|---|---|
| 调暗 / 房间 | 1 | 透视模式下是调暗层；在影院房间环境里换成房间层（二选一） |
| 发光（可选） | 1 | 画面周围的环境光 |
| 画面 | 2 | 左右眼各一层（关闭 3D 时 1 层） |
| 字幕 | 1 | |
| 控制条 | **1** | 退出键、播放键、片名、进度条、时间、调整按钮**全在一张贴图里**，命中测试在贴图坐标里做 |
| 弹出卡片 | 1 | 快捷菜单、下一集、投屏请求、缓冲、错误共用这一个槽位，**同时只出现一个** |
| 提示 | 1 | 和控制条不同时出现 |
| 射线 + 光标 | 2 | |
| 手柄模型 | 1 | |
| **合计** | **11** | 实际同时最多 10 层（toast 和控制条互斥） |

各状态的实际层数（画稿右上角有标注）：

| 状态 | 层数 | 组成 |
|---|---|---|
| 快捷菜单 | 9 | 调暗 1 · 画面 2 · 字幕 1 · 控制条 1 · 卡片 1 · 射线 2 · 手柄 1 |
| 控制条 | 8 | 调暗 1 · 画面 2 · 字幕 1 · 控制条 1 · 射线 2 · 手柄 1 |

| 投屏请求 | 8 | 调暗 1 · 画面 2 · 字幕 1 · 卡片 1 · 射线 2 · 手柄 1 |

| 缓冲 | 4 | 调暗 1 · 画面 2 · 卡片 1 |
| 沉浸 | 4 | 调暗 1 · 画面 2 · 字幕 1 |

开启发光层的状态各加 1，最多 10。调试用的统计层只在开发版出现，不计入预算。

### 6.6 弹出卡片

全部用快捷菜单的位置（控制条上方、右缘对齐），一次只出一个。优先级：错误 > 投屏请求 > 下一集 > 快捷菜单。

| 卡片 | 何时出现 | 内容与行为 |
|---|---|---|
| 下一集 | 片尾字幕开始时（有片尾标记就用标记，没有就在结束前 30 s） | 缩略图、「第 5 集 · 迷雾」、圆环倒数 8 s；「立即播放」（白）和「取消」。倒数结束就播下一集。不遮画面中央 |
| 投屏请求 | 看片时有设备投屏过来 | 「小林的 iPhone 想投屏到这里」、「《雾港》会暂停，并记住看到哪里」；「切换过去」（白）和「忽略」。**看片时不自动切换**，即使是已经自动允许的设备也一样。20 s 不处理就算忽略 |
| 缓冲 | 缓冲**超过 500 ms** 才出现 | 画面中央一个药丸：转圈加「正在缓冲」，不显示百分比。超过 10 s 换成带「重试」的错误卡片 |

### 6.7 提示（toast）

- 用于摇杆改强度、快进快退的时间、「再按一次退出播放」。一行字，可以带一个状态指示（比如强度的四格）。
- 同时只出一个，新的直接**替换**旧的，不堆叠。显示 2.5 s，不接受点击。
- **控制条显示时不出 toast**：那时信息直接体现在控制条上（进度、时间）。

### 6.8 和现在的 TransportBar 有什么不同

参照：`player/.../local/TransportBar.java` 和 `xr_layers.c` 顶部的图层清单（只读，没有修改）。

| 现在 | 这个设计 | 为什么 |
|---|---|---|
| 进度条贴在**画面平面**底部（画面宽度减去两边各 2%，高约画面的 12%） | 独立的 quad，**1.4 m，在画面下方** | 不再挡画面。界面在画面的深度上，会和 2D 转 3D 后凸出来的内容打架（立体窗口冲突）；放到更近处就没有这个问题 |
| 控制条是药丸加 7 个按钮（退出、手柄、环境、设置、键盘、射线、3D），每个按钮一层，单是控制条状态就 14–17 层，要靠丢层压回 16 | 整条控制条 1 层，菜单 1 层，全场景最多 11 层 | 不需要丢层逻辑；剩下的余量可以给以后的功能 |
| 7 个按钮常驻 | 只留播放、进度、退出、「调整」。环境、3D、屏幕放进快捷菜单；手柄和键盘只在电脑串流时出现（§6.9） | 看片时最常用的是暂停和拖进度，其余是偶尔调一次的设置 |
| 进度和悬停色是青色 `#7FD4FF` | 进度用琥珀，悬停用放大加提亮 | 青色像系统控件，在电影画面上跳。悬停不靠变色，色弱用户也能分辨 |
| 悬停进度条时，右边的总时长被换成悬停位置的时间 | 右边**始终是剩余时间**，悬停时间放在进度条上方的气泡里 | 同一个位置的数字不应该变成另一种意思 |
| 片名只在暂停时出现，26 texel（约 0.8°）、60% 白 | 片名常驻，1.1°，text-2（7 : 1 以上） | 低于 1° 的汉字读不清 |
| 进度条 10 texel 粗（约 0.3°），命中区是条高的 ±35% | 视觉 0.3°，悬停 0.5°，**命中区固定 2.5° 高** | 线细好看，命中区宽好点 |

### 6.9 电脑串流时的控制条（只写规则，没有画稿）

- 同一张贴图、同一位置。进度条换成「书房 Mac · 串流中」加延迟和码率（只有出问题时才显示数字，比如延迟 > 60 ms 时变红）。
- 「调整」左边多出「键盘」「手柄」两个按钮，总宽度不变。快捷菜单多一个「串流」标签（分辨率、码率、鼠标模式）。

## 7 Compose 落地说明

- **画布与密度**：设计按 1280×720 画。要先确认 PICO 2D 窗口里 **1 px 是否等于 1 dp**（窗口的 density）。如果不是，所有 token 按 dp 统一换算，比例不变。
- **悬停**：PICO 把射线投到 2D 窗口时，应该会发 `ACTION_HOVER_ENTER / MOVE / EXIT`。用 `Modifier.hoverable(interactionSource)` 加 `interactionSource.collectIsHoveredAsState()` 驱动放大和底色。**要在头显上确认确实收得到 hover 事件**。
- **放大用 `graphicsLayer { scaleX; scaleY }`**，不改 layout 尺寸，这样邻居不会被挤动，也不会触发重新布局。
- **关掉默认的 ripple**（`indication = null`，自己画按下态）：水波纹在低 PPD 下只是一团白光，而且和悬停放大重复。
- **滞回**：在命中框外扩 8 px 的 `pointerInput` 里判定离开，或者给 hover 加 80 ms 的离开延迟，二选一，在头显上比较效果。
- **骨架延迟**：用 `LaunchedEffect` 等 300 ms，数据还没到才显示骨架。
- **列表**：海报行用 `LazyRow`，配合 `snapFlingBehavior` 吸附到卡片边缘；分类网格用 `LazyVerticalGrid(GridCells.Fixed(6))`。
- **字体**：系统 Noto Sans CJK，只用 400 / 500 / 600 三个字重。数字开 `fontFeatureSettings = "tnum"`。
- **VR 场景内的贴图**：和现在的 TransportBar 一样，用 Android Canvas 画进一张 bitmap 再上传。只在状态变化时重画（悬停目标变化、播放和暂停切换、每秒的时间）。命中测试在贴图坐标里做，各控件的矩形和画图共用同一份常量。
